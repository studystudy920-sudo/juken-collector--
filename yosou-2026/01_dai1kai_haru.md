# 午前II 予想問題（四肢択一・19問）

### 〔分野〕暗号・認証・PKI(パスキー/FIDO2/OAuth/OIDC含む)

**問1** OAuth 2.0 の認可コードフローに PKCE(Proof Key for Code Exchange)を適用する主目的として、最も適切なものはどれか。

- ア アクセストークンを JWT 形式にし、リソースサーバでの署名検証を可能にする。
- イ 認可サーバとリソースサーバ間の通信を相互 TLS で保護する。
- ウ 悪意のあるアプリによる認可コードの横取りを防ぎ、正規クライアント(元の認可要求を出した主体)だけがトークンと交換できるようにする。
- エ リフレッシュトークンの有効期限を延長し、再認可の頻度を下げる。

**正解**: ウ
**解説**: PKCE(RFC 7636)は主にネイティブ/SPA など公開クライアントでの認可コード横取り(Authorization Code Interception)対策。クライアントが認可要求ごとに `code_verifier`(高エントロピー乱数)を生成し、そのハッシュ `code_challenge`(通常 S256)を認可要求時に送付、トークン交換時に元の `code_verifier` を提示する。認可サーバがハッシュ照合することで、コードを横取りした第三者は `code_verifier` を知らずトークン交換できない。なお選択肢ウは「検知」ではなく「交換の阻止(binding)」が本質である点に注意。ア・イ・エはいずれも PKCE の目的ではない。

**問2** FIDO2/WebAuthn によるパスキー認証がフィッシングに耐性をもつ根本的な理由として、最も適切なものはどれか。

- ア 認証のたびにワンタイムパスワードを生成し、一定時間で失効させるため。
- イ 署名対象データにアクセス先のオリジン情報がバインドされ、RP(リライングパーティ)がオリジンの一致を検証するため、偽ドメインでは署名検証が成立しない。
- ウ 秘密鍵をサーバ側にも複製保管し、突合により本人性を確認するため。
- エ 利用者が入力したパスワードをソルト付きハッシュで保存するため。

**正解**: イ
**解説**: WebAuthn ではブラウザが生成する clientData に乱数チャレンジとオリジンが含まれ、認証器はそのハッシュ(および rpIdHash を含む authenticatorData)に署名する。RP は署名検証時に、clientData 内のオリジンおよび authenticatorData 内の rpIdHash が期待値と一致するかを検証するため、オリジンの異なる偽サイトでは検証に失敗する。加えてブラウザは資格情報を rpId に紐づくオリジンでしか呼び出さない。ウは誤りで秘密鍵は認証器内に留まりサーバへ渡らない。OTP やパスワードハッシュ(ア・エ)はフィッシング耐性の本質ではない(AiTM 中継で OTP は突破され得る)。

**問3** OpenID Connect(OIDC)における ID トークンに関する記述のうち、適切なものはどれか。

- ア ID トークンは JWS で署名された JWT であり、iss・aud・exp・(要求時は)nonce 等のクレームを検証して初めて認証結果として信頼できる。
- イ ID トークンは認可(アクセス権の委譲)そのものを表し、リソースアクセスに直接使用する。
- ウ ID トークンの署名検証には、クライアントとサーバで事前共有した対称鍵のみを用いる。
- エ ID トークンは平文の JSON であり、TLS 上で送るため署名は不要である。

**正解**: ア
**解説**: OIDC は OAuth 2.0 上に構築した「認証」層で、ID トークン(JWT)により「誰が認証されたか」を伝える。受信側(クライアント/RP)は署名(公開クライアントでは通常 RS256、JWKS から `kid` で公開鍵取得)と iss(発行者)/aud(自分宛か)/exp(期限)を必ず検証し、リプレイ防止のため要求時は nonce も照合する。イはアクセストークンの役割で認証と認可の混同、ウは非対称鍵(RS256/ES256 等)が一般的で「対称鍵のみ」は誤り、エは改ざん検知のため署名が必須で誤り。

### 〔分野〕ネットワーク・クラウド・ゼロトラスト（SASE/SSE, DNS, メール認証, mTLS）

**問4** 権威DNSサーバの応答の完全性・出自を公開鍵署名で検証する技術と、その技術が担わない役割に関する記述として、最も適切なものはどれか。

- ア DNSSECはリソースレコードにデジタル署名(RRSIG)を付与し、DS/DNSKEYによる信頼の連鎖で完全性・出自認証を保証するが、通信路の暗号化は行わない。
- イ DNSSECはDNSクエリ・応答の全体をTLSで暗号化し、経路上の盗聴を防止する。
- ウ DNS over HTTPS(DoH)はリソースレコードに署名を付与し、キャッシュポイズニングを署名検証で防ぐ。
- エ DNSSECはカミンスキー攻撃の緩和には無効であり、権威サーバ応答の真正性は保証しない。

**正解**: ア
**解説**: DNSSECはRRSIG署名と、親ゾーンのDSから子ゾーンのDNSKEYへ至る信頼の連鎖により、応答の完全性・出自認証(データ由来認証)を提供し、キャッシュポイズニングやカミンスキー攻撃の緩和に有効。ただしレコードは平文で流れ、機密性(暗号化)は提供しない。通信路の暗号化はDoH/DoTの役割で、イ・ウ・エは役割の取り違えや誤り。

**問5** ゼロトラストアーキテクチャ(NIST SP 800-207)やAPIのサービス間通信で用いられるmTLS(相互TLS)の説明として適切なものはどれか。

- ア サーバ証明書のみを検証し、クライアントはパスワードで認証する片方向TLSである。
- イ クライアントとサーバの双方が証明書を提示して相互に認証し、証明書にバインドしたトークン発行(証明書バウンドトークン)にも利用される。
- ウ TLSハンドシェイクを省略し、事前共有鍵のみで通信を高速化する方式である。
- エ クライアント証明書の代わりにSPFレコードで送信元の正当性を検証する方式である。

**正解**: イ
**解説**: mTLSはサーバ・クライアント双方が証明書を提示して相互認証を行うTLS。ゼロトラストのサービス間通信やAPI保護に用いられ、OAuth 2.0のmTLS(RFC 8705)では発行トークンをクライアント証明書に紐づける証明書バウンドトークンにより、トークン盗用時の悪用を防ぐ。アは通常のサーバ認証型(片方向)TLS、ウ・エはmTLSと無関係。

### 〔分野〕Web/アプリケーション脆弱性(OWASP, SQLi/XSS/CSRF/SSRF, セキュアコーディング)

**問6** Webアプリケーションにおいて、クラウド環境のインスタンスメタデータエンドポイント(例: 169.254.169.254)へアプリケーションサーバから意図しないHTTPリクエストを送信させ、一時的な認証情報を窃取する攻撃がある。この攻撃の名称はどれか。

- ア クリックジャッキング
- イ サーバサイドリクエストフォージェリ(SSRF)
- ウ セッションフィクセーション
- エ ディレクトリトラバーサル

**正解**: イ
**解説**: SSRFはサーバに任意の宛先へリクエストを送らせる攻撃で、クラウドのインスタンスメタデータサービス(IMDS、169.254.169.254はリンクローカルアドレス)から一時認証情報を窃取する経路として悪用される。IMDSv2への移行、宛先の許可リスト化、名前解決後IPの検査による内部・リンクローカル宛て遮断が対策となる。

**問7** プレースホルダ(バインド機構)を用いたSQL文の組み立てが、SQLインジェクション対策として有効である最も本質的な理由はどれか。

- ア SQL文が実行前に暗号化され、通信経路上で解読されないため
- イ 入力値がSQL文の構文要素ではなくデータ(値)としてのみ扱われ、構文構造が変化しないため
- ウ 危険な文字列を検出した時点でDBMSがトランザクションをロールバックするため
- エ アプリケーションからDBへの接続がTLSで保護され改ざんが検知されるため

**正解**: イ
**解説**: プリペアドステートメントではSQL文の構文構造をあらかじめ確定(コンパイル)させ、後からバインドされる入力値は常にデータとして扱われる。ゆえに入力に含まれる引用符やSQL断片が構文として解釈されず、注入が成立しない。アプリ側のエスケープ処理に依存しない点が本質。なお、テーブル名・列名など構文要素そのものを動的に指定する箇所はバインドできないため、許可リストによる別途対処が必要である。

**問8** 利用者ブラウザに保存された正規のセッションIDが、XSSやセッションフィクセーションによって悪用されるのを防ぐ実装として、適切でないものはどれか。

- ア ログイン成功の直後にセッションIDを再発行(regenerate)する
- イ セッションCookieにHttpOnly属性とSecure属性を付与する
- ウ セッションIDをURLのクエリ文字列に付与して各画面間で受け渡す
- エ 一定時間操作がない場合にセッションをタイムアウトさせる

**正解**: ウ
**解説**: URLにセッションIDを載せるとRefererヘッダや閲覧履歴、プロキシ・アクセスログを通じて漏えいし、セッションハイジャックのリスクを高める。アはセッションフィクセーション対策、イはXSSによる窃取と盗聴の緩和、エは放置端末からの悪用低減であり、いずれも適切なセッション管理策である。

### 〔分野〕AIセキュリティ・LLM(OWASP LLM Top10, プロンプトインジェクション, RAG, AIエージェント, MITRE ATLAS)

**問9** OWASP Top 10 for LLM Applications 2025 における "間接プロンプトインジェクション(Indirect Prompt Injection)" に該当する攻撃はどれか。

- ア 攻撃者がチャット画面の入力欄に「これまでの指示を無視せよ」と直接打ち込み、システムプロンプトの制約を解除させる。
- イ 攻撃者が公開Webページやメール本文に人間には視認しにくい指示文を埋め込み、それをLLMがRAGや要約の過程で読み込んで実行してしまう。
- ウ 攻撃者がLLMのAPIに大量かつ長大な推論要求を送り、応答遅延とコスト増を引き起こす。
- エ 攻撃者が学習用データセットに悪意あるサンプルを混入させ、特定入力で誤動作するバックドアを仕込む。

**正解**: イ
**解説**: 間接プロンプトインジェクションは、いずれもLLM01:2025 "Prompt Injection" の一類型で、利用者の直接入力ではなく、LLMが処理対象として取り込む外部データ(Webページ・メール・添付文書・検索結果)に指示を潜ませ、利用者を介さずに実行させる点が特徴。アは利用者入力に直接注入する直接プロンプトインジェクション(同じくLLM01)、ウはLLM10:2025 "無制限消費(Unbounded Consumption)"、エはLLM04:2025 "データとモデルのポイズニング(Data and Model Poisoning)"。攻撃経路(利用者入力か外部データか)と攻撃フェーズ(推論時か学習時か)で切り分ける。

**問10** OWASP LLM05:2025 "不適切な出力処理(Improper Output Handling)" に起因する被害として最も適切なものはどれか。

- ア LLMが生成したHTMLやスクリプトを無検証でWebページに埋め込んだ結果、格納型XSSが発生する。あるいは生成された文字列をそのままシステムコマンドやSQLに渡した結果、コマンドインジェクションやSQLインジェクションに連鎖する。
- イ 多要素認証の時刻同期がずれ、ワンタイムパスワードの検証に失敗して正規利用者がログインできなくなる。
- ウ ベクトルDBのアクセス制御不備により、他テナントの文書が検索結果に混入する。
- エ AIエージェントに過大なツール実行権限を与えた結果、意図しない外部操作が行われる。

**正解**: ア
**解説**: LLM05はLLMの出力を「信頼できない外部入力(信頼境界の外側)」として扱わず、下流のブラウザ・DB・OS・APIへ無検証で渡すことでXSS/SQLi/コマンドインジェクション/SSRF/RCEへ連鎖する問題。ウはLLM08:2025 "ベクトルと埋め込みの脆弱性"、エはLLM06:2025 "過剰な代理権限"。イはLLM固有の脆弱性ではなく認証運用(可用性)の問題であり、LLM05とは無関係。

**問11** RAG(Retrieval-Augmented Generation)を用いた社内文書検索チャットボットにおいて、OWASP LLM08:2025 "ベクトルと埋め込みの脆弱性(Vector and Embedding Weaknesses)" として顕在化するリスクはどれか。

- ア 生成された回答の根拠が提示されず、利用者が誤情報を過度に信頼する。
- イ ベクトルDBに対する権限フィルタリングが不十分で、利用者が本来閲覧権限を持たない他部署・他テナントの文書を検索結果として取得できる。
- ウ プロンプトに含まれるシステム指示が応答に出力され、内部構成や制約が推測される。
- エ 長大なコンテキストの投入によって推論コストが急増する。

**正解**: イ
**解説**: LLM08はRAGで用いるベクトルDB・埋め込みに固有の脆弱性で、アクセス制御不備・マルチテナント分離不足による横断的な情報漏えい、埋め込みからの元データ復元(embedding inversion)、汚染文書の混入などが中心。対策は検索時の権限フィルタリング(利用者コンテキストでの絞り込み)とテナント/インデックス分離。アはLLM09 "誤情報"、ウはLLM07 "システムプロンプトの漏えい"、エはLLM10 "無制限消費"。

**問12** 生成AIの安全機構(ガードレール)を巧妙な言い回しやロールプレイ指示などで回避し、本来は出力が禁止されている内容を引き出す攻撃を何と呼ぶか。

- ア ジェイルブレイク(脱獄)
- イ データポイズニング
- ウ メンバーシップ推論
- エ モデル抽出

**正解**: ア
**解説**: ジェイルブレイクは、モデルの安全機構(ガードレール)を回避して禁止出力を得る手法で、プロンプトインジェクション(特に「これまでの指示を無視せよ」型)と組み合わせて問われる。イは学習データの汚染(LLM04)、ウは特定データが学習に使われたかを推定するメンバーシップ推論、エはAPI経由でモデルの機能を複製するモデル抽出/窃取。

### 〔分野〕マルウェア・攻撃手法・インシデント対応（MITRE ATT&CK, ランサムウェア, EDR/XDR）

**問13** MITRE ATT&CK(Enterprise)における Tactics、Techniques、Procedures(TTP)の関係の説明として、適切なものはどれか。

- ア Procedures は攻撃者の最終目的を表す最上位の分類であり、その下位に Tactics と Techniques が位置づけられる。
- イ Tactics は攻撃者が達成しようとする目的(What)を表し、Techniques はその目的を達成する手段(How)を表す。個々の攻撃者による具体的な実装が Procedures である。
- ウ Techniques は個別の攻撃で観測された IP アドレスやファイルハッシュなどの侵害指標(IOC)そのものを指す。
- エ Tactics は T 番号、Techniques は TA 番号で識別され、両者は 1 対 1 に対応する。

**正解**: イ
**解説**: Tactics=目的(What)、Techniques=手段(How)、Procedures=特定の攻撃者による具体的な実装、という3階層が核心。IOC は Procedures よりさらに個別・低抽象度の指標であり、汎用的な手法分類である Techniques とは異なる。識別子は Tactics が TA 番号、Techniques が T 番号(サブテクニックは T####.###)で、対応も 1 対 1 ではない(1 つの Technique は複数の Tactics に属し得る)。エは番号の割当てが逆で、かつ「1 対 1 対応」も誤り。

**問14** サイバーキルチェーン(Lockheed Martin)と MITRE ATT&CK の対比として、最も適切なものはどれか。

- ア いずれも攻撃を時系列の直線的な段階として順序づけたモデルであり、両者は同一の 7 段階から成る。
- イ ATT&CK は経営層への全体像説明に、キルチェーンは SIEM/EDR の検知ルール設計にそれぞれ特化している。
- ウ キルチェーンは偵察から目的実行までを直線的な段階で示すモデルであり、ATT&CK は攻撃手法を網羅的に整理したマトリクス型のナレッジベースである。
- エ ATT&CK は攻撃側、キルチェーンは防御側の対策をマッピングしたフレームワークであり、両者は排他的に使い分ける。

**正解**: ウ
**解説**: キルチェーンは「線」(偵察〜目的実行の直線的 7 段階モデル)、ATT&CK は「面」(順序を前提としない網羅的な手法辞書/マトリクス)という整理が定番。アは「ATT&CK も同一 7 段階の直線モデル」とする点が誤り。イは役割が逆で、検知ルール設計や脅威ハンティングにこそ ATT&CK を用いる。エの「防御側対策のマッピング」に相当するのは D3FEND であり、両者を排他的に使い分けるという整理も誤り(実務では相補的に併用する)。

**問15** インシデント対応におけるディジタルフォレンジックスで、揮発性の高い情報から順に証拠保全を行う原則(Order of Volatility)に従うとき、最も優先して取得すべきものはどれか。

- ア ハードディスク上のログファイル
- イ CPU レジスタ・キャッシュおよびメモリ上の情報
- ウ 定期バックアップ用の磁気テープ
- エ 監視カメラの録画データ

**正解**: イ
**解説**: 揮発性の高い順に保全するのが原則で、CPU レジスタ・キャッシュ・メモリ上の情報(実行中プロセス、ネットワーク接続状態、復号された暗号鍵などを含む)が最優先。以降、ディスク上のログ、バックアップ媒体、物理記録媒体の順に揮発性が下がる。電源断でメモリ情報は失われるため、活性(ライブ)状態での採取が重要となる。

### 〔分野〕セキュリティマネジメント・法規・ガイドライン(ISMS, リスクマネジメント, 個人情報保護法, サプライチェーン/SBOM)

**問16** 2022年4月に全面施行された改正個人情報保護法に関する記述のうち,適切なものはどれか。

- ア　取り扱う個人情報の量にかかわらず,一定の要件を満たす漏えい等が発生した場合,個人情報保護委員会への報告及び本人への通知が原則として義務化された。
- イ　仮名加工情報は,他の情報と照合しない限り特定の個人を識別できないように加工した情報であり,第三者への自由な提供が認められている。
- ウ　外国にある第三者へ個人データを提供する場合,本人の同意があれば移転先国の制度に関する情報提供は不要である。
- エ　保有個人データの開示請求において,本人は書面による交付のみを請求でき,電磁的記録による提供を求めることはできない。

**正解**: ア

## 問4　AI エージェント導入とガバナンス

## 問5　SOC における検知強化とフォレンジック

（分野: マルウェア・攻撃手法・インシデント対応（MITRE ATT&CK, ランサムウェア, EDR/XDR））

F 社は EDR と SIEM を導入し、外部委託の MDR で 24 時間監視している。ある日、SOC から「経理部端末が業務時間外に外部の見慣れない IP へ定期的に外向き通信(コネクトバック)を行っている」とのアラートが上がった。EDR のプロセスツリーには、正規の文書アプリから起動された PowerShell が難読化スクリプトを実行し、その後 C2 サーバと疑われる宛先へ一定間隔で接続する挙動が記録されていた。SOC 責任者 G 氏は、封じ込めと原因究明のため、当該端末をネットワークから隔離しつつ揮発性情報を保全する方針を立てた。あわせて、今回のように「正規プロセスから起動されたスクリプトによる不審通信」を今後 ATT&CK に基づき体系的に検知・評価できる体制を整えたいと考えている。

設問1 マルウェアが感染端末側から外部の C2 サーバへ向けて自ら接続を確立する通信形態の一般名称を答えよ。また、この形態が境界型ファイアウォールを通過しやすい理由を述べよ。
設問2 当該端末を隔離した後、電源を切らずに活性(ライブ)状態で揮発性情報を先に保全する理由を、証拠保全の原則の観点から述べよ。
設問3 「正規プロセスから起動された PowerShell による難読化スクリプト実行」に対し、EDR がシグネチャ照合ではなく有効に働く検知アプローチを一つ挙げ、その理由を述べよ。
設問4 G 氏は、自社の検知ルールが ATT&CK のどの技術をカバーし、どこに検知の空白があるかを可視化したい。この目的に適した ATT&CK 関連ツールの名称を答えよ。

**解答例**:
- 設問1: 名称=コネクトバック(バックコネクト)通信。理由=多くの境界型ファイアウォールは内部から外部へのアウトバウンド通信(特に HTTP/HTTPS 等の一般的なポート)を広く許可しているため、感染端末が内側から外向きに接続を確立する形態は、正規の業務通信に紛れて通過しやすいから。
- 設問2: メモリ上のプロセス、ネットワーク接続状態、復号鍵などの揮発性情報は電源断で消失するため、揮発性の高い順に保全する原則(Order of Volatility)に従い、実行中の状態を保った活性(ライブ)状態でこれらを先に取得する必要があるから。
- 設問3: アプローチ=プロセスの親子関係や一連の挙動に着目した振る舞い検知(ふるまい/ヒューリスティック検知。文書アプリ→PowerShell 起動→難読化実行→定期外部通信という連鎖の異常性を評価)。理由=難読化された未知の亜種はシグネチャ照合を回避できるが、正規プロセスから正規ツール(PowerShell 等)を悪用する Living off the Land 型の挙動は、実行の連鎖や通信パターンを監視することで検知できるから。
- 設問4: ATT&CK Navigator。

**採点のポイント**: 設問1は「コネクトバック/外向き(アウトバウンド)通信」と、内部→外部の発信が広く許可されている点を理由として押さえていること。設問2は揮発性情報が電源断で消失する点と Order of Volatility に触れていること。設問3はシグネチャの限界(未知・難読化・正規ツール悪用)に対し、プロセス連鎖や振る舞い/挙動ベース検知が有効である理由まで説明できていること。設問4は検知カバレッジとギャップの可視化ツールとして ATT&CK Navigator を挙げていること(SIEM や SOAR は不可)。

## 問7　AI時代の脆弱性管理体制の見直し

（分野: AI駆動型サイバー攻撃・フロンティアAI（自律型攻撃/防御, デュアルユース, AIガバナンス））

設問1　攻撃のAI化により、K社の従来運用（四半期ごとの一括適用）が特に危険となる理由を、「リードタイム」という語を用いて40字以内で述べよ。

設問2　限られたリソースで対応するための優先順位付けの観点を二つ挙げよ。
